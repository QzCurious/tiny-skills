# Ground in Context

先辨識下一個有效行動需要可靠理解的內容與仍缺少的資訊，只取得足以消除實質不確定性的相關脈絡。

從現有對話、User 明示的來源、可用的 Context Artifacts、專案慣例與環境開始。依主題所需的權威性、時效性與範圍判斷來源，並只在會影響理解時追蹤相關來源。區分來源直接支持的內容、可由脈絡合理推得的假設，以及仍未知的事項；遇到衝突時保留差異及其來源。

當所需資訊缺少時，先從可用脈絡取得，而非要求 User 重複提供。若資訊無法取得，明確說明缺少什麼、為何無法取得，以及缺口會如何影響後續；只有當不同答案會實質改變結果且 User 可能補足資訊時，才請 User 提供或決定。若仍能在清楚揭露的假設或縮小的範圍內可靠繼續，據此進行；否則停止後續解讀、細化或行動，並提出可解除阻礙的資訊或路徑。

當下一個有效行動已有足夠脈絡，且所有會實質改變結果的未知事項皆已取得、由明確假設承接，或有可行的解決路徑時，即完成 grounding。
